# 서버 작업 요청: 조직 문서함(RAG) 검색 스코어링/랭킹 품질 문제

> **상태: 서버측 해결 (2026-07-14, open-moai 커밋 `b74e35268` 배포).**
> 실측 결과 원인이 둘로 나뉘었고, 서버가 고칠 수 있는 쪽은 고쳤습니다. 요약은 아래 "## 해결" 참고.
> **CLI 쪽에서 알아야 할 핵심: 이 트레이스가 나온 조직 문서함에는 문서가 3개뿐이고, AI 관련
> 문서는 사실상 1개뿐이었다. 즉 "동일 문서가 1위"의 상당 부분은 랭킹 버그가 아니라 코퍼스가
> 얇은 데이터 문제였다.** (`AI Law Issue Brief` 문서는 KB에 실존하지 않았음 — 아래 참고.)

## 해결 (2026-07-14)

### 원인 분리
1. **스코어 포화 = 서버 코드 버그 → 수정 완료.**
   `performHybridSearch` 의 `normalizeScores` 가 **Min-Max 정규화**라 컬렉션 top 이 항상 정확히
   `1.00` 이 됐다. 코사인 0.5 짜리 "보통 매치"가 완벽 매치(1.00)처럼 보여, CLI 가 "더 좋은 게
   있을 것"이라 오판하고 재검색을 반복한 실질 원인. → **Min-Max 제거, 실제 벡터 코사인 유사도를
   그대로 최종 score 로 보고**하도록 변경(정직한 0~1 분포). 랭킹도 이 정직 스코어 기준.
2. **데이터 sparsity = 코드로 못 고침(운영/데이터 이슈).**
   트레이스가 나온 org 컬렉션에는 문서가 **3개**(카페 매출 분석 21청크 / 회의정리 6 / AI 거버넌스
   9)뿐이고, **AI 정책 주제 문서는 `AI 거버넌스 핵심 동향과 정책 시사점` 단 하나**였다. 따라서
   모든 AI 질의가 그 문서를 1위로 반환한 것은 **정상 검색**이다. 리포트가 "뒤로 밀린다"고 본
   `Artificial Intelligence Law Issue Brief` 문서는 **KB에 존재하지 않았다**(에이전트의 가정).
3. **HyDE 과다적용 = 부차 → 완화.**
   `shouldApplyHyDE` 가 24자 이상이면 무조건 HyDE 발동이라 사실상 모든 질의가 일반적 가상문서로
   수렴했다. → **6단어 이상 키워드-풍부 질의는 HyDE 스킵**(짧은/개념 질의만 유지).

(더 이상 전부 1.00 이 아님). 카페 질의(0.70)가 AI 질의(0.55)보다 높은 것은 코퍼스 내 매치

### CLI 쪽 액션
- 이제 score 가 정직하므로 **낮은 score(예: < 0.4)면 "약한 매치/얇은 코퍼스"로 해석해 재검색을
  멈추는** 휴리스틱을 권장(과거엔 전부 1.00 이라 이 신호가 없었음).
- 문서함에 문서가 3개뿐인 것은 **데이터 보강**의 문제 — 검색 품질 체감을 높이려면 조직 문서함에
  실제 문서를 더 넣어야 함. 서버 검색 로직은 이제 질의를 정상 반영함.

정직한 스코어 + CLI MaxTurns 25 상향이 함께 작용.

**3. 남은 과잉 검색 = 코드가 아니라 데이터(코퍼스) 이슈로 확정.**
수정 후에도 검색 횟수 편차 큼(실측 8~21회). 스코어가 이제 정직한데도 반복하는 이유는 값이 전부
"중간"(0.5~0.7)이고 아주 높은 게 없어서 — 모델이 "더 좋은 게 있을 수도" 하며 각도를 바꿔 탐색.
근본은 **AI 주제 문서가 3~5개뿐인 얇은 코퍼스**. → **조직 문서함에 문서를 더 넣으면 케이스가
풍부해지고 상위 매치의 스코어·변별력이 올라가 자연히 개선됨.** CLI/서버 코드로 더 짜낼 것은 없음.

> CLI 결론: 스코어링 버그(서버) = 해결 / 완주 문제(CLI) = 해결 / 잔여 = 데이터 보강 대기.

## 증상 → 영향
- 능력 있는 모델(gpt-5.6 계열)은 결과가 변별되지 않으니 **질의를 11~20회 바꿔가며 재검색** →
  RAG 호출 낭비 + 지연 + (턴 예산 소진 시) 작업 미완. CLI 는 기본 MaxTurns 를 25로 올려 완주는
  시켰지만, 이는 증상 완화일 뿐 근본 원인은 서버 검색 품질입니다.
- 약한 모델은 그냥 첫 결과를 받아쓰므로 **한 문서만 반복 인용**하는 편향된 요약이 나옵니다.

## 원인 후보 (RAG 팀 확인 요망)
1. **스코어 정규화가 1.0 에 포화** — 코사인 유사도/리랭커 점수를 min-max 등으로 정규화하며 top-1 이
   항상 1.0 이 되는지. 원 점수(정규화 전)를 로깅해 확인.
2. **특정 문서의 임베딩 지배** — `AI 거버넌스 핵심 동향과 정책 시사점` 문서가 중복 청크/과대 길이/
   특이 임베딩으로 모든 질의에 최상위로 매칭되는지(임베딩 중복·정규화 문제).
3. **하이브리드 검색 가중치** — FTS + 벡터 결합 시 한쪽이 상수 점수를 뱉어 랭킹을 지배하는지
   (`performHybridSearch` 의 결합 로직).
4. **쿼리 확장 붕괴** — `queryExpansion.allQueries` 가 모든 입력을 유사한 확장으로 수렴시키는지.

## 기대치 (what good looks like)
- [ ] 서로 다른 질의는 서로 다른 top 문서를 반환(질의 특이성이 랭킹에 반영).
- [ ] 스코어가 0~1 구간에 **분포**(전부 1.00 이 아니라 실제 유사도 차이 반영).
- [ ] "행정명령 14110 제4조" 같은 구체 질의는 해당 주제 문서를 상위로.
